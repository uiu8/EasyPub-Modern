## 0. 这份文档解决什么问题

本项目的主流程已经稳定：

导入书稿 → 检查与修复 → 制作设置 → 转换与验收

当前界面的问题不在于缺少按钮，而在于视觉层级失控：

1. 页面之间的视觉语言不一致；
2. 主按钮过大、过重，把注意力从当前问题带到了马上转换；
3. 导入书稿页原本清晰的批量书稿布局被新视觉稿破坏；
4. 章节工作台的依据、范围、证据和后果没有始终处于可见层；
5. 按钮文字没有稳定表达会改变什么；
6. 水墨元素被当成装饰图片使用，没有形成可复用的设计系统。

本规范的目标是：保留原 UI 已验证的功能骨架，重新建立一套清新、克制、可执行的黄纸水墨视觉系统。

本规范不允许通过重写前后端来解决视觉问题。当前代码已经有完整的 WPF 入口、Core 修复链、备份事务、转换设置和验收链，应采用渐进式 UI 重构。

## 1. 设计结论

### 1.1 必须保留的原 UI 骨架

原 UI 截图中以下结构是正确的，后续视觉改造不得删除或隐藏：

- 顶部项目栏：当前项目、搜索、主题/设置、快照提示；
- 左侧固定流程栏：1 导入书稿、2 检查与修复、3 制作设置、4 转换与验收；
- 左侧底部工具：转换记录与验收、原文备份、快捷键管理；
- 主内容区的页面标题、说明、副标题；
- 页面自己的操作栏，而不是把所有操作堆进全局底栏；
- 底部输出栏：输出格式、排版方案、状态、检查问题、开始转换；
- 导入书稿页的批量列表、筛选、排序、拖拽导入和“全选当前列表”。

这些区域已经对应 MainWindow.xaml、MainWindow.Workflow.cs、转换设置面板和任务中心的逻辑。视觉重构应围绕它们做减法。

### 1.2 需要改变的部分

- 全局只保留一个当前页面的主行动，但主行动不等于每页都显示大黑按钮；
- 主行动高度 36–42px，只有转换提交、应用高影响方案时可升到 44px；
- 普通操作使用轻量描边按钮或文字按钮；
- 查看、定位、预览、切换、筛选不得使用主按钮样式；
- 修改 TXT、删除重复正文、应用方案、开始转换必须显示影响范围；
- 水墨渐变用于按钮表面、选中态和少数状态强调，不做满屏深色背景；
- 水墨背景必须低对比、可关闭，不能影响文字阅读和截图验收。

## 2. 用户任务模型

| 用户任务 | 需要看到的事实 | 允许的主要操作 |
|---|---|---|
| 导入一批书稿 | 文件是否加入、格式、状态、来源 | 添加、拖入、移除、筛选、排序 |
| 判断章节问题 | 问题是什么、证据在哪里、是否影响成品 | 定位、预览、加入方案、忽略 |
| 选择修复方式 | 使用当前书稿还是参考目录；改章节树还是改 TXT | 切换依据、切换应用范围、查看差异 |
| 生成并验收成品 | 用哪个引擎、输出到哪里、检查是否通过 | 检查、转换、打开输出、查看记录 |

每个按钮必须服务于其中一个任务。不能为了“看起来丰富”增加没有后果说明的按钮。

## 3. 全局信息架构

### 3.1 页面层级

MainWindow

- 顶部项目栏：EasyPub Modern、当前项目、全局搜索、快照提示、设置；
- 左侧流程导航：1 导入书稿、2 检查与修复、3 制作设置、4 转换与验收；
- 左侧工具：转换记录、原文备份、快捷键；
- 主工作区；
- 底部输出栏：输出格式、排版方案、当前状态、检查问题、开始转换。

### 3.2 顶部栏的职责

顶部栏只放跨页面的上下文，不放章节修复动作。

| 控件 | 作用 | 不应承担的功能 |
|---|---|---|
| 当前项目 | 切换或创建工程 | 不直接修改 TXT |
| 全局搜索 | 搜书名、问题、章节标题 | 不替代章节工作台内搜索 |
| 快照提示 | 恢复、暂不恢复、删除快照 | 不自动恢复 |
| 设置 | 全局主题、规则、默认引擎 | 不放本次书稿动作 |

### 3.3 底部栏的职责

底部栏是“输出准备状态”，不是所有页面的操作面板。

- 没有书稿时显示准备导入；
- 有必须处理的问题时，开始转换禁用并显示原因；
- 检查通过时显示可转换；
- 章节工作台仍保留输出状态，但不抢占工作台主行动；
- 检查问题打开检查页，不直接修改内容；
- 开始转换使用当前已确认设置和已应用方案，不自动应用未确认修复。

## 4. 视觉系统：黄纸、水墨、印色

### 4.1 设计关键词

暖纸，不做脏旧复古；墨色，不做纯黑大块；留白，不做装饰堆叠；印色，只用于确认和少量提醒。山水只做边缘气息，不做主体背景。控件优先保证可读、可定位、可操作。

### 4.2 色彩令牌

建议在 App.xaml / ThemeManager.cs 中建立统一令牌，控件不得继续在页面内散落颜色常量。

| 令牌 | 建议值 | 用途 |
|---|---|---|
| PaperCanvas | #F4F0E7 | 应用背景 |
| PaperSurface | #FBF9F3 | 卡片、列表、输入区 |
| PaperRaised | #FFFDF8 | 浮起面板、弹窗 |
| Ink900 | #263038 | 标题、主文字 |
| Ink700 | #4E5D66 | 次要文字、图标 |
| Ink500 | #78858A | 辅助说明、禁用文字 |
| InkWashStart | #2F414B | 渐变水墨按钮起点 |
| InkWashEnd | #71858D | 渐变水墨按钮终点 |
| Cinnabar | #A76A4E | 待确认、人工介入 |
| Ochre | #B39455 | 目录、建议、轻提醒 |
| Jade | #6C8178 | 通过、已完成 |
| Line | #D9D4C9 | 分隔线和边框 |
| Focus | #8A6E3B | 键盘焦点环 |

禁止使用纯黑作为整块主按钮背景，也禁止使用纯白作为大面积页面底色。

### 4.3 水墨渐变按钮

水墨按钮不是黑色矩形，也不是高饱和渐变：

- 渐变方向：左上到右下；
- 起点 InkWashStart，终点 InkWashEnd；
- 圆角 7–9px，高度 36–42px；
- 默认无阴影，悬停只增加极轻的纸面浮起感；
- 按钮内只放一个动作名称和一个方向图标。

状态：悬停亮度提升约 6%；按下亮度降低约 8%；禁用回到纸色底；键盘焦点使用 2px Focus 外圈，不能只依赖颜色。

### 4.4 水墨背景

采用低对比 SVG/PNG 素材，优先放在窗口边缘，透明度建议 8%–14%。不使用实时粒子、WebGL 或持续动画。默认静态，设置中可关闭。高对比模式自动隐藏。截图测试必须在无背景装饰时仍然通过。

## 5. 控件和按钮层级

| 级别 | 视觉 | 典型动作 |
|---|---|---|
| L1 主行动 | 渐变水墨填充 | 应用方案、备份并修改 TXT、开始转换 |
| L2 次行动 | 纸色填充加细边框 | 添加书稿、选择目录、检查问题、打开设置 |
| L3 工具动作 | 透明或极浅底 | 定位原文、查看详情、预览、刷新 |
| L4 危险动作 | 印色描边或文字 | 删除快照、从原文删除副本、放弃方案 |

按钮文字必须包含动作和对象，必要时加范围。推荐“添加书稿”“选择参考目录”“预览处理方案”“应用到章节树”“备份并修改 TXT”“定位原文”“加入本次方案”“打开转换设置”“开始转换”“打开输出目录”。不推荐无对象的“确定”“处理”“执行”“修复一下”“下一步”。

以下动作必须在按钮附近显示后果：

| 动作 | 必须显示 |
|---|---|
| 应用到章节树 | 只影响本次成品结构，原始 TXT 不变 |
| 备份并修改 TXT | 先备份当前文件，再修改显示路径的 TXT |
| 删除重复正文 | 删除哪一份、删除多少行、如何恢复 |
| 应用参考目录方案 | 未定位正文不会被创建 |
| 开始转换 | 使用当前已确认设置和已应用方案 |

## 6. 四个主页面的布局与逻辑

### 6.1 导入书稿：必须沿用原 UI 的优秀布局

导入页是批量书稿管理台，不是空白欢迎页。布局固定为：

页面标题“导入书稿”与按钮“添加书稿”“导入文件夹”“从收藏导入”“更多”；其下是自动检查设置和已启用数量；再下是筛选、排序、书稿表格，底部是总数和全选。

要求：

1. 保留原截图中的顶部动作栏和表格列；
2. 空状态只作为列表区内容，不替代整页布局；
3. 添加书稿、导入文件夹是 L2；
4. 移除所选是 L4，只有选中后启用；
5. 更多收纳收藏夹、清理导入记录等低频动作；
6. 拖入只改变待导入列表，确认后才创建书稿状态；
7. 导入成功后显示格式、大小、路径、检查状态；
8. 底部开始转换只有存在可转换书稿且前置检查允许时启用。

导入页不得改成“中央巨大上传框加其他按钮消失”的设计。只改变纸张、边框、图标和按钮层级。

### 6.2 检查与修复：总览页

检查页回答“哪些书需要处理”，不直接展开所有章节细节。采用问题总表：状态、问题类型、条数、书稿、判断依据、下一步。

下一步必须按问题类别映射：

- 文件或制作设置：调整输出；
- 编号与层级：在工作台核对层级；
- 重复：在工作台对比这两份；
- 漏识别：在工作台预览补建；
- 需要参考目录：选择参考目录。

不能所有行都显示“编辑成品标题”。

### 6.3 章节工作台：三栏证据布局

章节工作台采用三栏：

- 左：章节目录、搜索、卷章树、断点标注；
- 中：待核对问题，包括章节错位、完整章节重复、标题缺失、正文未找到；
- 右：问题详情、当前位置、建议位置、原文证据、相似章节、定位原文、加入方案。

顶部两个选择始终可见：

- 检查依据：当前书稿线索 / 参考目录；
- 应用范围：仅整理章节树 / 修订文本副本。

检查依据决定证据来源；应用范围决定写入对象。切换依据会使旧预览失效，并提示重新生成。切换范围不会改变判断，只改变写入对象。右侧详情必须区分 TXT 位置、成品位置、证据、影响和未定位状态。

### 6.4 制作设置与转换验收

制作设置保留排版与字体、封面与书籍信息、输出设置三类页面，采用“设置项目—表单—Kindle/EPUB 预览”三栏。预览是当前设置结果，不是装饰图。封面上传保留拖入和选择文件。

转换页区分准备态、执行态、完成态。引擎名称和状态明确。完成态分别展示输出文件、格式大小、结构检查、目录检查、阅读器检查、打开目录和转换记录。“转换成功”“结构通过”“内容完整”“Kindle 真机通过”必须是四个独立状态。

## 7. 六类章节问题的 UI 映射

| 问题 | 详情必须显示 | 主动作 | 禁止行为 |
|---|---|---|---|
| 卷标题丢失 | 章号重启、候选边界、目录证据 | 预览分卷 | 无证据生成卷正文 |
| 完整章节重复 | 两份标题、正文相似度、原文行区间 | 对比正文，选择保留 | 仅凭同号自动删除 |
| 章节位移 | 当前卷、建议卷、前后邻章 | 预览归位 | 无目录自动猜卷属 |
| 连续重复标题 | 重复标题行、正文归属 | 合并节点或预览删除 | 连正文一起删 |
| 标题缺失 | 目录条目、候选正文范围、证据状态 | 定位或人工分割 | 创建空章冒充修复 |
| 标题写错 | 原标题、建议标题、规则可识别性 | 预览改标题 | 静默更换正则 |

问题状态必须同时显示证据状态和处理状态：已证实/有依据待确认/未定位/人工确认/不适用，以及未处理/已加入方案/已解决/已忽略。

## 9. 状态、提示和空状态

状态颜色只表达状态：墨蓝/青灰为普通信息，靛青为选中，芥末黄为建议或人工判断，朱砂为风险和删除，松绿色为通过，灰色为禁用或未执行。

空状态必须告诉用户下一步：“还没有书稿。添加 TXT / EPUB 文件，或将文件拖入当前列表。”并提供添加书稿和导入文件夹。错误提示必须同时说明哪里失败、原文件是否改变、是否已有备份和下一步。

## 10. 响应式和可访问性

- 1040px 为主窗口最小宽度基线，1440×900 为主要验收尺寸；
- 1280×800 必须保持标题、主动作和底部输出栏可见；
- 窄窗口优先压缩装饰和辅助说明，不压缩主文字；
- 默认使用 Microsoft YaHei UI，正文和按钮最低 12.5px；
- 所有按钮可 Tab 到达，焦点环清楚；
- Esc 关闭不保存弹窗，Ctrl+Z 只撤销当前工程动作；
- 删除、写入 TXT、恢复备份等高影响动作必须可键盘确认和取消；
- 不只用颜色区分状态，必须同时有文字或图标。

## 12. 分阶段实施计划

### P0：视觉基线冻结

固定原 UI 页面布局和操作入口，整理 App.xaml、Controls.xaml 的颜色令牌，建立按钮层级和状态表，为导入、检查、设置、转换各截一张基线图。

### P1：全局壳层与导入页

## 14. 参考方向

本项目只借鉴视觉语言，不复制其他项目的布局或代码：

- [ppt-master-plus 的 Ink Wash 视觉规范](https://github.com/gnuhpc/ppt-master-plus/blob/main/references/visual-styles/ink-wash.md)：宣纸留白、低饱和墨色、单一印色焦点；
- [XuanShu UI Gallery](https://github.com/tsingxuanhan/xuanshu-ui-gallery)：水墨、古典色和控制台信息层级；
- [ink-wash-website / inkview](https://skillsmp.com/ja/creators/qybaihe/inkview/skills-ink-wash-website)：宣纸表面、干笔边缘、青黛/朱砂点缀和文字安全区；
- [MoLan Obsidian Theme](https://www.obsidianstats.com/themes/obsidian-molan)：纸色主题与夜墨主题；
- [formwork-sumi](https://github.com/shellcat-com/formwork-sumi)：仅参考墨迹作为边缘材质，不采用 WebGL 动效。

参考原则：参考克制、留白和层级，不照搬山水插画；参考纸、墨、印色的材料关系，不把水墨变成黑色渐变；参考编辑软件的信息密度，不把界面改成海报。

## 15. 与既有开发文档的关系

# 章节工作台 v1.22.0 实施与验证

## 当前结论与边界

已提供本地可运行测试版，主要布局、分组处理流程，以及“无章节时建议数字章节并按本书一键识别”已实施；章节筛选也已统一为“全部章节 / 待核对”同组分段单选，并修复大章节树切换时的同步重复扫描卡顿。保留原有未提交修改，不覆盖旧版、不修改测试书稿、不上传 GitHub。本报告采用通用实施记录结构，不套用安全分析报告模板。

原规划的 54 个功能与 42 条验收场景尚未全部逐项验收；本报告不把编译通过等同于完整产品验收。

## 如何使用

1. 解压 `outputs/EasyPubModern-v1.22.0-filter-responsive-final-win-x64.zip` 的全部内容，再运行其中的 `EasyPub.Desktop.exe`。不要只提取 EXE，保留 config.xml 和 bin 目录。
2. 进入章节工作台，在左侧切换全部章节或待核对，按提醒类别筛选；搜索支持标题及 `行:51397`。
3. 右侧先核对原始标题和正文，再使用推荐操作。提醒不是自动删除许可。
4. Ctrl 多选，Shift 连选；勾选框仍只负责是否进入目录，不代表批量操作选择。
5. 批量还原以完整兄弟章节顺序分段，每段归入其前一个章节；保留误识别标题行和正文。不合法的组会说明跳过原因，需要确认后才部分执行。
6. 处理结果留在原处，可以撤销；使用底部上一组、下一组继续核对。
7. 识别设置放在顶部；移动、升降级、合并、改标题等放在“其他处理”；全书整理、目录批量开关、已确认提醒恢复和编辑器设置放在“更多”。
8. 保存章节树只提交到当前项目状态，还需要保存项目。原始 TXT 只会在明确调用外部编辑器后由用户编辑；重新激活窗口发现源文件变化时，旧行号操作与保存会被禁用，需要重新识别。
9. 如果转换前检查显示“没有识别到章节”，但原文存在多处 `001：标题`、`002：标题` 这类候选，打开章节工作台后会看到“发现疑似数字章节”。先核对候选原文，再选择“识别并规范标题”或“仅识别，保留原标题”；前者把成品目录标题转换为“第 X 章 标题”，后者保留 `001：标题`。两者都只给当前书建立本书规则，不开启其他书，也可撤销。

## 本次实现

- 左右分栏、可调整宽度；一份原始文本预览；上下文推荐操作和分组导航。
- 疑似正文误识别、重复标题、卷与层级、编号异常、疑似漏识别及其他提醒分类。
- 连续短数字条目组成核对组；转换前检查与工作台共用 ChapterReviewAnalyzer。
- 提醒默认装载最多 200 组，提供继续装载入口。此限制是展示限制，不是后台异步分页。
- 同组位置导航、当前处或本组处理、窗口内确认正常与恢复。
- 完整树顺序上的批量分段处理，部分无效组确认、结果保留、撤销重做。
- 重复标题清理支持当前组范围；原有全书清理、行数范围、忽略编号等入口保留。
- 规则弹窗、规则校验、现有本书/全局数字规则与命名方案继续可用。
- 原始标题与成品标题分开展示；长章定位超过预览长度时展开全文后定位。
- 新增识别来源元数据，用于避免把明确的手动章节作为数字误识别组。
- 无章节时的数字章节建议：至少两处候选、每处默认至少 3 行非空正文；过滤小列表和常见小数正文。候选仅提示，必须由用户点击识别。
- 数字章节识别提供两种一次性决策：规范成品标题，或保留原始数字标题；规范只作用于成品章节树，不回写 TXT。
- “全部章节 / 待核对”改为同一组分段单选按钮：同高、同样式、互斥选中；选中项使用浅色底和半粗字，悬停与提示说明保持一致。
- 筛选切换性能：提醒组按 `(Code, LineNumber)` 建立索引，组成员按节点 ID 定位；空确认集不再为每组生成确认键；节点状态只在值变化时通知 UI。634 章基准（含切换后的布局更新）从约 19 ms 降至约 2 ms，回归预算为单向切换小于 16 ms。

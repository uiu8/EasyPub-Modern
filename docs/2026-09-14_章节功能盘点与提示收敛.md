# 章节功能盘点与提示收敛（2026-09-14）

本文只做盘点与归因，不改变任何行为。所有条目均来自当前支线代码。

## 三、乱在哪：四个具体证据

### 1. 同一件事有多套术语
「重复」在系统里有 4 个 code、3 种叫法：**重复拼接区段**（`chapter_repeated_sequence`）、**重复正文**（`chapter_content_duplicate`）、**重复标题**（`chapter_duplicate`）、**重复章节**（`ref_duplicate_segment` 的 UI 类型名）。用户无法判断它们是同一类问题还是不同问题。

「漏识别」同样有 5 个 code：`chapter_unrecognized`、`chapter_heading_typo`、`chapter_unnumbered`、`numeric_chapters_suspected`、`chapter_number_gap`。

### 2. 分类轴有两套，而且互不一致
`IssueCategory.For` 分出：跳章 / 漏号、重复章节、编号重复 / 倒序、漏识别标题、分卷 / 结构、广告 / 文本清理、其他章节问题、文件 / 制作设置。

工作台左侧下拉框却是：全部问题、疑似正文误识别、重复正文、重复标题、编号异常、卷与层级、疑似漏识别、其他提醒。

两套名字不同、粒度不同、数量也不同（8 vs 8），筛选结果和分类标签对不上。

### 3. 同一个动作有多个入口
- **补建章节**：目录辅助面板的「检测并预览补建」、目录辅助面板的「依据参考目录调整章节树」、工作台右侧的「修复本组漏识别标题…」、预检窗口的「预览补建章节」——四处。
- **结构整理**：工作台顶部「结构整理…」、更多菜单「预览结构整理…」、预检窗口「预览结构整理」——三处。

### 4. 新旧能力职责重叠
`UnnumberedHeadings`（启发式：靠独立短行 + 上下空行 + 同名分段猜）和 `ReferencePlanner`（基准：靠官方目录定位）都能补建章节，但前者靠猜、后者有权威依据。目前两者并列在同一个面板里，用户不知道该用哪个。

## 四、建议的收敛方向

### 1. 分类轴只保留一条：按「用户要做的动作」
| 轴 | 含义 | 包含原 code |
|---|---|---|
| **认全** | 有内容但没成为章节 | `chapter_unrecognized`、`chapter_heading_typo`、`chapter_unnumbered`、`numeric_chapters_suspected`、`chapter_number_gap` |
| **去重** | 同一段内容出现多次 | `chapter_repeated_sequence`、`chapter_content_duplicate`、`chapter_duplicate`、`ref_duplicate_segment` |
| **归位** | 编号或层级不对 | `chapter_number_order`、`volume_number_duplicate`、`chapter_level_gap`、`chapter_structure_suggested` |

三个动作对应三个阶段，顺序天然：先认全 → 再去重 → 后归位。

### 2. 入口按「有无参考目录」二分，而不是按技术实现
- **有参考目录**（联网获取或导入）→ 一律走「依据参考目录调整章节树」，它是唯一能做补建 + 改题 + 去重 + 卷层级的入口。
- **无参考目录** → 只保留一个降级入口「无目录时的本地扫描」，把 `UnnumberedHeadings` 与结构整理收进去，明确标注「依据本地启发式，可能误判」。

工作台右侧只做**核对与单处处理**（定位、对比、还原、改标题），不再承担批量补建。

### 3. 提示分三级，而不是全都叫「提醒」
| 级别 | 含义 | 例子 |
|---|---|---|
| **必处理** | 不处理会导致成品结构错误 | 缺失章节、整本未识别、连续大段重复 |
| **建议处理** | 影响成品质量但可接受 | 标题写法差异、单章重复、卷号重复 |
| **仅供参考** | 本地多余、疑似但不确定 | `ref_extra_chapter`、`chapter_diagnostics_limit` |

### 4. 提示文案统一句式
现状是每处自造句式。建议统一为：

```
[动作] 在 <位置> 发现 <数量> 处 <问题>；<依据>；<建议动作>。
```

例：
> 补建 · 第 20266 行起发现 71 个章节未收录；依据官方目录第 6 卷第 10—80 章；建议在「依据参考目录调整章节树」中勾选补建。

## 五、当前不建议改的部分

- `ChapterDiagnostics` 的判定阈值（跳号、倒序、层级跳跃）——这些是保守启发式，改动风险高。
- `ValidatePlan` 的行分配规则——卷层级依赖它「只占用 ContentRanges」这一特性。
- 撤销链（`Mutate` / `_undo`）——所有修复都必须经过它，不能绕开。

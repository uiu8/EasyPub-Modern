## 1. 本步要解决的问题

### 2026-09-24 · 用户修正后的收口

- 章节工作台保留三栏结构：章节树、待核对、证据与原文；顶部保留“检查依据 × 应用范围”，底部保留撤销/重做、取消和“应用并返回”。
- 按用户最终要求恢复全局原版配色：`App.xaml` 与 `ThemeManager.cs` 回到仓库基线的宣纸灰、黑色主操作和原有状态色；移除本轮误加的灰黑渐变按钮资源。
- 导入、检查总览、制作设置、转换验收等其他页面不做架构重排。Kindling 引擎设置属于既有功能改动，继续保留；本步没有回退其设置项或转换逻辑。
- “底部栏消失”按两处核对：章节工作台底部提交栏已保留；其他页面的底部栏来自原页面布局与共享资源，未被本步删除，恢复资源后随原布局显示。

本次只修正视觉范围，不改变章节修复事务、参考目录依据、应用范围、Kindling 引擎或原文备份恢复逻辑。

此前工作台顶部把长文案、依据选择、目录入口、撤销重做和主操作放在同一排。窗口宽度变化时，按钮会被布局拉高，用户也无法分辨“检查”“选择目录”“预览方案”和“应用修改”的边界。

本步按预览图的工作流重新组织章节编辑页，但不改导入、检查总览、制作设置和转换验收页面的架构：

```text
检查依据 × 应用范围 → 检查章节 → 章节树 / 待核对 / 证据与原文 → 预览并应用
```

## 2. 已实施的界面结构

### 2.1 顶部决策条

- **检查依据**
  - `当前书稿`：只读取当前 TXT、当前章节树和当前规则，不读取参考目录，也不联网。
  - `参考目录`：通过原有“选择参考目录”入口选择、粘贴或获取目录；确认后才作为本次检查依据。
- **应用范围**
  - `仅整理章节树`：只更新成品章节树和项目记录，TXT 不变。
  - `同时修改 TXT`：仍然先进入逐项预览；只有可验证的文本动作被选中并应用后，才在备份后写入当前 TXT。
- **检查章节**：只生成问题与建议，不直接应用修复。
- `识别设置…`、`撤销`、`重做`、`专项处理`保持原有事件入口，作为次级操作，不再和主检查按钮争夺视觉权重。

顶部原先的三块大提示（参考目录 / 下一步 / 依据·应用范围·可撤回）已从视觉主流程移除。它们的事实仍由原有控件和状态方法维护，供恢复、测试和辅助流程使用；用户可见内容压缩成预览图式的一行状态：目录状态、识别规则、原文版本。应用范围的详细后果只在确认窗和页脚显示一次。

顶部的两个选择共同表达四种模式，实际应用模式会继续传入现有 `RepairReviewWindow`，确认窗仍可在应用前再次核对范围。

### 2.2 三栏工作区

1. **章节树**：按卷、章和断点显示当前已应用结构；树上的勾选仍表示目录收录/批量操作，不与问题选择混用。
2. **待核对**：统一显示问题组、数量和处理状态，提供“全部 / 可处理 / 需确认”筛选，并按问题类型进入既有处理入口。
3. **证据与原文**：显示选中问题的标题、依据、当前/建议位置、原文上下文和下一步操作；定位、重新识别、编辑副本、加入方案等原有按钮仍由原事件处理。

问题类型卡与 `ReviewCategory` 计数共用同一份诊断结果，避免卡片数字和列表数字出现两套口径。

## 3. 与设计文档的对应关系

| 设计要求 | 本次实现 |
|---|---|
| 两个独立选择组成四种组合 | 顶部“检查依据”与“应用范围”分别使用独立控件；选择范围缓存到本次工作台会话并传入确认窗 |
| 检查、加入方案、应用分阶段 | 主按钮只调用检查/生成方案；问题处理中栏负责选择；底部“应用并返回”仍是提交入口 |
| 参考目录不应被静默使用 | 当前书稿模式明确跳过已保存目录；目录入口仍需用户选择/确认 |
| 用户主权和可撤回 | 章节树操作继续走 `Mutate`；撤销/重做入口保留；写 TXT 的路径仍由备份和事务层执行 |
| 每个按钮说明后果 | 顶部依据、范围和主按钮均有可见标签与 ToolTip；主按钮文案改为“检查章节”，不再暗示已修复 |
| 问题列表与证据同步 | 中栏卡片通过既有问题选择事件驱动右栏详情和原文定位 |
| 视觉层级 | 章节工作台沿用预览图式的留白和三栏层级；全局资源恢复仓库原版配色，其他页面不重排架构 |

# EasyPub Modern v1.57.3 — 目录修复确认窗重做

这次改的是「一键修复目录」之后弹出的那个确认窗口。它以前是一整块只读文本，这次把它改成了可以逐项决定的界面；同时补上了上一版已经写好、但还没发布的**多源更新**能力。

## 目录修复确认窗

**以前的问题**：窗口把 264 个「未定位章节」的标题全部平铺出来，你真正想看的「实际变化」被推到几百行之外；而且窗口里**一个复选框都没有** —— 按下按钮就直接套用软件预设的选择，你没法取消其中任何一项。

**现在的样子**：

- 首屏四个数字，一眼看清这本书到底缺没缺：

  ```
  补齐        处并回      章需你核对    章疑似公告
  （随勾选变化）          （目录事实，不随勾选变化）
  ```

  前两个跟着你的勾选实时变化，后两个是目录本身的事实、不会变。某本书实测是
  `6 / 0 / 6 / 26`：要核对的只有 6 章，另外 26 章是聚合站收进来的请假条。
- 左侧分类常驻，每类显示已选数量（如 `2/2`）；右侧明细只滚自己的内容，251 条也不会把别的分类顶掉。
- **每一项都有复选框**，勾掉就不执行。每行写清楚"在哪一行、会变成什么"，例如
  `第 41 行　第13章 余烬　→ 当前标题「第13章 夜行」与参考目录「第13章 余烬」不同；勾选后使用参考标题`。
- 窗口**可以拉伸**，不再固定大小。

### 264 章里大多数不是缺章

聚合站的目录会把作者的请假条一起收进去。现在这些**没有章号的条目**单独归为「疑似公告」，不再和真正的缺章混在一个数字里 —— 你要核对的只剩个位数，而不是两百多条。

判定依据只用「目录里有没有章号」，没有引入"请假""休更"这类关键词：关键词会随站点写法变化，而章号判据是硬的。

### 保持不变的安全约定

- 原始 TXT 不会被修改；应用前自动备份，应用后可以撤销。
- **你手工编辑过的章节永远不参与自动修改。**
- 目录里没有、你树里有的章节默认一律保留，只有你主动勾选才会并回正文。
- 目录和文件对不上时，仍然要你先勾「已核实参考目录确属本书此版本」才能应用。

## 多源更新（上一版已写好，本次首次发布）

更新检查现在按 `GitHub → AtomGit` 顺序尝试，第一个能应答的源胜出。之前 GitHub 直连不畅时更新检查会失败，现在会自动回退到 AtomGit 镜像。

## 怎么验证的

- `EasyPub.Core.Tests` **414 通过 / 0 失败**
- `EasyPub.Desktop.Tests` **127 通过 / 0 失败**
- 新增 9 个测试锚定行为契约：无章号条目归入「疑似公告」、verdict 文案与拆分数字不会互相矛盾、**每个复选框都能映射回方案里恰好一个动作**、默认勾选等于方案自身的选择、取消一行只减一项、窗口可缩放、首屏数字随勾选变化、左栏已选数会变。
- 另外用探针渲染**真实窗口**（不是设计稿、也不是示例数据）核对了浅色、深色和各个分类页。这一步抓到了两个单元测试覆盖不到的问题：取消勾选后首屏数字不更新、以及明细区重建会把用户的取消操作静默撤销。两处都已修掉。

## 还没验证的

- **本版安装包的自更新路径没有单独实测。** 发版后会按惯例跑一次真实更新验证（用上一版便携版当"已装旧版本"，走 检查更新 → 关闭程序 → 自动覆盖重启 的完整链路），结果以实际运行为准。
- AtomGit 同步脚本 `publish-atomgit.ps1` 的**完整创建路径**本次是首次实跑（该平台 release 无法删除，此前只能用同一版本反复手动验证每一步）。发布时会盯住它的输出。

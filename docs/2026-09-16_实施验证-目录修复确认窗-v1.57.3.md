## 2. 原窗口为什么"简陋"（已复查确认）

不是没信息，是顺序把重点埋了。旧 `ChapterAutoRepairPanel` 把文本拼成一个只读 `TextBox`：
参考来源 → verdict → **264 个未匹配标题** → 分类账目 → 最后才是「实际变化」。
窗口 580 高、默认停在顶部，用户真正想看的东西在几百行之外。

更关键的是**没有任何复选框**：`apply.Click` 直接 `DialogResult = true`，随后套用
`plan.DefaultSelection`。底层其实早就具备逐项选择的条件（`ReferenceAction.Recommended`
就是为此准备的），只是 UI 从未暴露。

## 4. 两个必须知道的实现细节

### 4.1 为什么不能直接再调一次 `ReferencePlanner.Apply`

预览（`Build`）已经用 `plan.DefaultSelection` 套用过一次，`outcome.Entries` 是那次的结果。
确认窗里若再对 `snapshot.Entries` 跑 `Apply`，等于让同一棵树自己验证自己；而且
`Apply` 内部会再调 `RepairIntegrity.Verify`，行守恒一旦不满足就抛异常。

`RebuildWithSelection` 是唯一同时知道"用户选择"和"卷重建"的地方：它用原始
`document.Entries` 重算，并按 `outcome.VolumeRestartIndexes` 重放推断卷那一步。
**重启点不从重建后的树反推** —— 那是另一个问题。

### 4.2 主题必须用 `SetResourceReference`，不能直接读 `Application.Current.Resources`

`ThemeManager.Apply` 是替换 `Application.Current.Resources` 里的画刷实例。
构造时直接取 `(Brush)Application.Current.Resources["..."]` 会**钉死**在当时的主题上，
深色模式不生效。窗口全部用 `SetResourceReference(...)` 才跟随主题（实测已确认）。

新增测试锚定的是**行为契约**，不是实现细节：

### 视觉验证抓到、单测没覆盖的两个问题

1. **取消勾选后首屏数字不更新**：`Refresh()` 只更新了左栏与页脚，漏了统计块。
   首屏正是这次改造的全部价值，那里的数字过期比没有数字更糟。已改为按当前选择计数。
2. **`BuildChangeList` 会被 `Refresh()` 的 `Children.Clear()` 一起清掉**：
   它原本放在 `_detailItems` 里，而 `Refresh` 会清空该面板。

第 2 个问题还牵出一个更严重的隐患：`Refresh` 原本在明细区**重建行**，新建的
`CheckBox` 会按 `Recommended` 重新变回勾选 —— **用户取消的勾选会被静默撤销**。
现已把行与标题分离：行只在切换分类时重建一次，`Refresh` 只改标签。

> 教训与交接文档 §5 第 8 条一致：**测试通过不等于界面对**。
> 单测走的是视觉树断言，量不出"数字过期""勾选被撤销"这类需要跑起来看的问题。

### AtomGit 同步被平台拒绝：仓库被判为镜像仓库

```
POST /api/v5/repos/Wohl/EasyPub-Modern/releases
400 {"error_code":400,"error_code_name":"UN_KNOW",
     "error_message":"gitcode: this operation is not allowed because the repository is an image repository."}
```

**关键证据**：`v1.57.2` 是 **2026-09-16 15:25:30** 在**同一个仓库**上成功创建的。
也就是说这个限制是在那之后才生效的 —— 仓库被开启/标记成了镜像仓库（AtomGit 后端是 GitCode，
对镜像仓库禁止创建 release）。

排除了其他可能：

- 不是令牌问题：同一令牌 GET `/releases/latest` 返回 200。
- 不是请求体问题：最小 payload（仅 `tag_name`）同样 400。
- 不是脚本问题：`tools/publish-atomgit.ps1` 的创建调用与 v1.57.2 成功时完全一致。
- 仓库字段看着正常：`fork=false`、`repository_type=code`、`public=true`、`default_branch=main`。
  所以"镜像"是平台侧的同步设置，不是仓库可见属性。

**留下的状态**：AtomGit 上仍只有 `v1.57.2`，tags 到 v1.57.2 为止。400 不会创建任何东西，
所以没有残留垃圾（已核对 release 与 tag 列表）。

**要解决它，只能由用户在平台上操作**：到 AtomGit/GitCode 该仓库的设置里关闭镜像/导入同步，
或新建一个普通仓库再配进去。这不是代码能绕过的。

**影响面**：客户端更新检查按 `GitHub → AtomGit` 顺序尝试、第一个能应答的胜出。
GitHub 直连正常的用户**已经能看到 v1.57.3**；只有 GitHub 不可达、依赖回退的国内用户
仍会停留在 v1.57.2。所以这是一个"降级可用"状态，不是发版失败。

**备选**：`docs/RELEASING.md` §3.5 提到的 Gitee 镜像 `FFs-7/EasyPub-Modern`（交接文档 §4 第 3 条，
当时"一行没做"）现在价值上升了 —— 它是 AtomGit 之外的第二条国内回退路径。

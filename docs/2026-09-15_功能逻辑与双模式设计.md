# EasyPub Modern 功能逻辑与双模式设计

**读这一份可以回答**：这个软件由哪些模块组成、一本书从导入到成品经过哪些判断、以及"有参考目录"和"没有参考目录"两条路径在**同一功能**上分别做了什么。

版本基线：v1.55.1（提交 `583d0d4` 之后）。

---

## 1. 产品目标与三条硬约束

以**官方目录**为准重建章节树，但**绝不因此丢失正文、绝不覆盖用户的编辑**。

| 约束 | 落地方式 | 违反时的行为 |
|---|---|---|
| **正文守恒** | 每个源行要么进某个章节，要么进移除清单 | `RepairIntegrity.Verify` 逐行核对，不守恒就**抛异常停止应用** |
| **用户主权** | 用户删过、改过、手动添加的，重新修复不能翻案 | 手动条目 `RecognitionSource = "manual"`，任何对齐都不动它 |
| **可核对** | 每次删除都有逐行清单 + 源文件 SHA-256 | `RepairIntegrity.SaveRemovedAsync` 写移除清单；无清单不删除 |

原始 TXT **永不原地修改**：一切改动走 `Mutate`（可撤销快照），导出才落到成品文件。

## 2. 双模式的判定依据：`RecognitionSource`

整个软件只有**一个开关**决定走哪条逻辑：

```
树里存在 entry.RecognitionSource == "reference"  →  有目录模式（严格对齐）
否则                                            →  无目录模式（本地启发式）
```

它由 `ReferencePlanner.Apply` 写入（第 237 行）：被参考目录对齐过的条目标 `reference`，
卷边界标 `reference-volume` / `inferred-volume`，用户手改的标 `manual`。

下游据此换逻辑的地方共四处：

| 位置 | 有目录 | 无目录 |
|---|---|---|
| `ChapterReviewAnalyzer.Analyze` | 抑制 6 类本地猜测类提醒，**保留** `chapter_number_gap` | 全部提醒都出 |
| `ChapterAutoRepair.Build` | 走 `ReferencePlanner` 对齐 | 直接返回"未取得参考目录，无法判断完整性" |
| `ChapterBreakpoints` 的标注 | 额外给出"目录里有、源文本找不到"的章节标题 | 只给"编号之间断了" |
| 工作台话术 | "按参考目录调整章节树" | "依据本地规则推断，可能误判" |

## 3. 模块地图

### 3.1 识别与树模型

| 文件 | 职责 |
|---|---|
| `HeadingSyntax.cs` | **所有**标题识别规则的唯一来源；`ParseNumber` 把中文章号转数字 |
| `ChapterTree.cs` | `ChapterTreeDocument`：源行 + 条目 + 识别选项；`LoadAsync` 建初始树 |
| `ChapterEditingDocument.cs` | 编码探测、逐行候选（`ChapterCandidate`） |
| `NumericHeadingRule` / `NumericHeadingFilter` | "1 标题"这类数字章节的正则与最小正文行数过滤 |

建树流程（`ChapterTree.LoadAsync`）：三级模式（卷/章/节）→ 自定义 `chapterPattern` →
数字章节规则（可选）→ 生成条目。**开头未识别的行**进一个 `IsFrontMatter = true` 的"序"。

### 3.2 诊断层（只读，从不改树）

| 文件 | 产出 |
|---|---|
| `ChapterDiagnostics.cs` | 逐条扫描：章号跳变、编号倒退、层级跳跃、卷号重复、同名重复、疑似未入树的标题行 |
| `MissingChapterHeadings.cs` | **跳章区间内**疑似漏识别的标题（含"久=九"这类编号纠错表） |
| `UnnumberedHeadings.cs` | 异常长章里的无编号标题（同名分段系列，或与目录标题匹配） |
| `ChapterStructureSuggestion.cs` | 多处结构信号同时出现时给"建议整理结构" |
| `ChapterRepeatedSequences.cs` / `ChapterContentDuplicates.cs` | 重复拼接区段、同名章节正文相似度 |
| `ChapterBreakpoints.cs` | 把"哪里断了"整理成可渲染的断点（供章节树行间标注） |
| `ChapterReviewAnalyzer.cs` | 把上面全部折叠成**分组**，并在这里执行双模式抑制 |

### 3.3 参考目录层

| 文件 | 职责 |
|---|---|
| `ReferenceCatalog.cs` | 多书源并发抓取公开目录（`<dl>/<dt>/<dd>` 优先，其次同前缀链接组）；预算：搜索 6s / 单源 15s / 并发 4 |
| `ReferenceLocator.cs` | **三遍定位**：候选集 → 间隙补位 → 兜底全文搜索（章号 / 标题词 / 字符相似度 0.67） |
| `ReferenceAlignment.cs` | 加权全局对齐（Needleman-Wunsch）+ `TitleKey`（章号与标题词分开比较） |
| `ReferencePlan.cs` | 生成可复核的**动作清单**并应用 |
| `CatalogCache.cs` | 按书名的目录查询缓存（24h） |
| `ReferenceCatalogInput.cs` | 按源文件 SHA-256 保存/读取本书目录；`Pick` 选最大候选 |
| `BookSource.cs` | 书源顺序与启用状态 |

### 3.4 修复与守恒

| 文件 | 职责 |
|---|---|
| `ChapterAutoRepair.cs` | 一键修复主流程 + 分类报告（`RepairReportGroup`） |
| `RepairIntegrity.cs` | 行守恒校验、移除清单 |
| `ChapterStructureRecovery.cs` | 无可用卷标题时的按章号重启点重建（本地） |

## 4. 一本书的完整流程

```
导入 TXT
  │
  ├─(1) 识别建树      ChapterTree.LoadAsync
  │
  ├─(2) 诊断          ChapterReviewAnalyzer.Analyze
  │        └─ 分组、分类（漏识别/误识别/重复/编号与层级/其他）
  │
  ├─(3) 取得参考目录？（双模式分岔点）
  │        ├─ 有：书源并发抓取 → 三遍定位 → 加权对齐 → 动作清单
  │        └─ 无：本地启发式（MissingChapterHeadings / UnnumberedHeadings / Recovery）
  │
  ├─(4) 预览与勾选     人在回路：默认只勾"仅新增结构"的安全项
  │
  ├─(5) 应用           ReferencePlanner.Apply 或 本地修复的 Apply
  │        └─ RepairIntegrity.Verify 不守恒即抛异常
  │
  ├─(6) 备份与清单     源文件快照 + 逐行移除清单
  │
  └─(7) 转换导出       EasyPubConverter（EPUB / MOBI，可接 KindleGen）
```

### 各阶段的双模式差异

| 阶段 | 有目录 | 无目录 |
|---|---|---|
| (2) 诊断 | 抑制 `chapter_unrecognized` / `chapter_number_order` / `chapter_heading_typo` / `chapter_content_duplicate` / `chapter_duplicate` / `chapter_repeated_sequence`；**保留** `chapter_number_gap` | 全部启用 |
| (3) 缺章判定 | **可判定**：目录有 `N` 章、树里有 `M` 章，差多少就是差多少 | **不可判定**：只能说"编号之间断了"，且只在跳章区间里找候选 |
| (3) 标题差异 | 以目录写法为准，逐条列出 `Retitle` | 只能靠 `SuggestCorrectedTitle` 从左右邻章推断错号 |
| (3) 卷结构 | 按目录的卷建立层级（`reference-volume`） | 靠"章号从 N 回到 1 且后面跟着 2、3"推断分卷（`inferred-volume`） |
| (3) 重复正文 | 目录只出现一次 → 可判定重复，正文一致时默认移除 | 只能按相邻同名 + 正文相似度提示 |
| (3) 目录外章节 | 明确列为"参考目录未列出，需你决定"（`KeepExtra`，默认保留） | 不适用 |
| (5) 应用 | `ReferencePlanner.Apply`：先定章节边界，再按边界分配正文，最后重新编号层级 | 各启发式模块自己的 `Apply`（如 `MissingChapterHeadings.Repair`、`UnnumberedHeadings.Apply`） |
| 完成后 | 条目标 `reference`，后续诊断自动进入有目录模式 | 条目标 `manual` / 原识别来源 |

### 三个不变量（两种模式都必须满足）

1. **不发明章节**：只补建**文本里真正定位到**的标题（铁律 4）
2. **不丢正文**：`Apply` 里"取消章节身份"只移除标题边界，那些行落回前一章的正文范围
3. **可撤销**：每个动作都是普通章节树编辑，走 `Mutate` 快照

## 5. 双模式的完整对照表

| 维度 | 有参考目录 · 严格对齐 | 无目录 · 本地启发式 |
|---|---|---|
| **依据性质** | 权威（官方目录说哪些章存在） | 猜测（从正文形态推断） |
| **缺章/多章** | 与目录逐章对比，可判定 | 本地规则推断，不可判定 |
| **重复** | 目录只列一次 → 可判定 | 同名 + 相似度，需人工确认 |
| **标题** | 以目录写法为准 | 左邻右章推断 |
| **卷** | 目录给出卷边界 | 章号重启点推断 |
| **完整性结论** | "已对齐 836/837 章；未定位 1 章" | "未取得参考目录，无法判断完整性" |
| **误判风险** | 目录本身可能不属于这本书（有"来源与文件不匹配"判定） | 标题写错、分卷重启、正文列举都可能被误判 |
| **用户必须做的** | 核对目录外章节、确认重复项 | 逐条核对每一个候选 |

**关键点：同一个功能码在两种模式下走完全不同的实现。**例如"补建漏识别标题"：

- 有目录：`ReferencePlanner` 的 `AddChapter` 动作——目录已知这一章存在，定位器在三遍扫描里找它的行号
- 无目录：`MissingChapterHeadings.Find`——只在前一章的正文范围里、按"编号落在 [低+1, 高-1]"、且符合三种格式化错误之一才接受

## 6. 工作台 UI 如何映射这些逻辑

### 6.1 两个界面，同一功能的两种呈现（易错点）

| 界面 | 实现 | 内容 |
|---|---|---|
| 主窗口「检查与修复」页 | `MainWindow.Workflow.RefreshWorkflowRows` | 全部书稿的提醒总表，按类别筛选，同类折叠 |
| `PreflightWindow`（弹窗报告） | `PreflightWindow.Collapse` | 单次检查的报告 |

> 这两个界面**必须分别改**。v1.52.0 曾只改了弹窗，等于没改（见 §4.2 的教训）。

### 6.2 章节工作台的动作清单

| 问题码 | 按钮 | 点击后 |
|---|---|---|
| `chapter_unrecognized` | 从选中行建立章节 | 把选中源行变成章节边界 |
| `chapter_number_gap` | 补建本组 N 个漏识别标题… / 批量补建全书的 N 处… / 获取参考目录并对照… | 三档递进，文案与行为对应 |
| `chapter_heading_typo` | 修复本组漏识别标题… | `MissingChapterHeadings.Repair` |
| `chapter_unnumbered` | 预览补建 / 获取参考目录… | `UnnumberedHeadings` + 目录 |
| `numeric_chapters_suspected` | 识别并规范标题 | 重新识别 + 章号规范化 |
| `chapter_content_duplicate` | 对比正文，选择保留… | 逐对比较 |
| `chapter_repeated_sequence` | 定位另一段开头 | 只导航 |
| `chapter_structure_suggested` | 预览结构整理… | `ChapterStructureRecovery` |
| `chapter_number_order` / `volume_number_duplicate` / `chapter_level_gap` | 核对层级处理…（有精确改号建议时优先"修改为：…"） | 打开动作菜单 |

映射由 `ChapterIssueAction` 集中管理，并有测试锁住"每个问题码都有对应操作"
（`tests/EasyPub.Desktop.Tests/ChapterIssueActionTests.cs`）。

### 6.3 章节树上的行间标注（v1.55.0）

`ChapterBreakpoints.Between` 产出三类断点，渲染在两行之间：

| 类型 | 含义 | 有目录时的额外信息 |
|---|---|---|
| `NumberGap` | 章号之间断了 | 号码可信时逐章列举（≤30 个），否则降级为"编号对不上，请核对" |
| `ReferenceMissing` | 目录里有、源文本找不到 | 直接给出标题：「第六百八十九章 奥秘」 |
| `HeadingTypo` | 编号写法接不上 | 只在跳章区间内、且号码能解释缺口时报 |

## 7. 已知的设计取舍与限制

| 项 | 现状 | 原因 |
|---|---|---|
| 目录覆盖率 | 需用户点「获取参考目录（联网）」或走手动核对面板 | 不在用户背后发网络请求 |
| 混用编号体系的书 | 《择天记》这类中文/阿拉伯章号混排会有较多"编号对不上"提示 | 跨体系比较无法判定，只能如实提示 |
| 番茄**关键词搜索** | 不做 | 需逆向字节风控签名，已试到底；目录页免签名可用 |
| 无目录时弱化手工核对 | 不做 | 用户已确认保留手工路径 |
| 缺章如实报告 | 不粉饰 | 铁律 3：软件不会凭空造出章节 |

## 8. 想改某处时看哪里

| 想改什么 | 改哪个文件 | 连带要改 |
|---|---|---|
| 标题识别规则 | `HeadingSyntax.cs` | `HeadingSyntaxTests` |
| 新增一类提醒 | `ChapterDiagnostics.cs` 或专用诊断类 | `IssueCategory.For` 的分类、`ReviewCategories`、工作台卡片分支、`ChapterIssueAction` |
| 诊断的抑制策略 | `ChapterReviewAnalyzer.Analyze` 的 `referenceAligned` 过滤 | 相关回归测试 |
| 目录抓取 | `ReferenceCatalogClient` | `BookSourceCatalog`、书源设置 |
| 定位精度 | `ReferenceLocator` | `ReferenceLocationStats` 观察命中分布 |
| 修复动作 | `ReferencePlan.Build/Apply` | `RepairIntegrity.Verify` 必须仍通过 |

# EasyPub Modern v1.57.0：应用内更新

2026-09-16，基于 v1.56.3（0a0bc70）。

## 新增：软件自己检查和安装更新

从这一版起，新版本**不用再手动下载安装包**：

- **设置 → 更新与关于** 新增「检查更新」，显示当前版本、新版本号与该版本的更新说明。
- 下载完成后点「立即重启更新」即可；**也可以什么都不做**——下次关闭软件时会自动完成覆盖并重启。
- 新增「启动时检查更新」开关（默认开启）：只在后台查询并提示，**不会自动下载或安装**。
- 发现新版本时，工作区状态栏提示「发现新版本 x.y.z；打开「设置 → 更新与关于」可立即更新」。

**升级不会动你的数据**：设置、恢复快照、目录缓存都在 `%LOCALAPPDATA%\EasyPub Modern`，
与程序目录分离，覆盖程序文件不影响它们。原本在进行的项目与书稿也不受影响。

## 修复

- **设置页的版本号一直是错的**：那里硬编码显示 `v1.42.0`，标题栏显示的却是真实版本。
  现在改为从程序集读取。（主界面修过同一个问题——`MainWindow.xaml.cs` 里留着当时的注释
  "app showed v1.42.0 in the corner while the titlebar said v1.43.2"，设置页当时漏了。）

## 更新是怎么落地的

下载 → 解压校验 → 写一份待应用记录 → 由独立的 PowerShell 脚本在主程序**退出之后**覆盖程序文件并重启。

脚本会等进程真正退出（并继续探测 exe 句柄确实释放，避开杀软扫描）、先备份原程序文件、
覆盖失败自动重试并从备份回滚、无论成败都重新启动程序。过程日志留在
`%TEMP%\EasyPubModern-Update\staging\apply-update.log`。

## 验证

- Core 测试 **389/389**（新增 58 项：版本解析与比较、发布响应解析、下载与落地脚本、待应用记录）。
- Desktop 测试 **123/123**。
- **真实网络端到端**：检查更新往返 709 ms，正确识别远端 v1.56.3 并挑出便携包（而不是安装包）；
  实际下载 68,087,283 字节、7.0 秒（约 9 MB/s），字节数与发布页声明一致，解压后内容齐全。
- 设置页已离线渲染检查。

### 端到端验证暴露并修掉的两个真实缺陷

1. 更新包与解压目录同名，解读压前会清空目录，**把要解压的源文件自己删掉了**。
2. 发布包带一层顶层目录，不摊平会让落地脚本把整个目录复制进程序目录，**更新后 exe 不在原来的位置**。

两条现在都有单元测试钉住（`Update_archive_is_kept_outside_the_staging_directory`、
`Staging_with_a_single_top_level_folder_is_flattened`）。

### 尚未验证的部分

- **安装版（Setup）的自更新路径未单独实测**。它与便携版共用同一套覆盖逻辑，且 Inno Setup 用的是
  `PrivilegesRequired=lowest`（装到用户可写目录），因此预期同样可用，但没有单独跑过。
- 只验证了"当前版本低于远端"与"当前版本等于远端"两种判定；"远端版本低于当前版本"
  （例如回退到旧版后）按代码逻辑不会提示更新，未实测。

## 下载

- **便携版（推荐）**：`EasyPubModern-v1.57.0-in-app-update-win-x64.zip`
  解压到任意目录，运行 `EasyPub.Desktop.exe`，无需安装。
- **安装版**：`EasyPubModern-Setup-v1.57.0-x64.exe`

从 v1.56.x 升级：直接解压覆盖便携版目录（或运行新版安装包）。
**也可以让 v1.56.3 自己更新到这一版**——下次启动时它会提示发现新版本。

按钮与布局规划

风格沿用现在的：近黑实心主按钮 · 白卡片 · 浅灰描边 · 琥珀色只用于警示，字号沿用现有层级。 改的是按钮的数量与层级——三屏加起来 30 多个按钮，其中一大半和主行动等重， 所以用户必须自己判断哪个是对的。
规则一句话：每屏只留一个实心按钮；危险动作离开主行；同一个动作的多个入口合并。

主窗口 · 导入书稿 现有按钮 8 个 → 4 个

这屏最大的问题不是按钮多，而是没有任何一句话说"下一步做什么"——用户看到一张表，要自己判断。

现在决定改后理由
+ 添加书稿 导入文件夹 从收藏导入 ▾ 合并 添加书稿 ▾（含 文件 / 文件夹 / 收藏） 三个入口做的是同一件事。它们等重，用户就得先读三个标签再选。
移除所选 ▾ 更多 移出主行 选中行时才出现，放在列表下方 移除所选 ▾ 删除是危险动作，不该和「添加」并排等重；「更多」是垃圾桶，能收就收。
开始转换所选 1 本 保留 开始转换所选 1 本（唯一实心） 它本来就是这屏的目标动作，位置和样式都对。
检查问题 改名降级 转换前检查 名字要和侧栏第 4 步「转换与验收」对得上；「问题」这个词让人以为坏了。
查看并处理（建议处理 201） 改文案升权 处理 201 项提醒 「查看并处理」没说处理什么。把数字放进按钮，点之前就知道要面对多少事。
编辑章节结构 编辑封面信息 文本清理 保留降级 同位置，去掉边框改成 编辑章节结构 › 它们是有边框的次按钮，看起来和「处理提醒」一样重要——实际是可选深入操作。
（缺） 新增 底部状态条加一句：下一步：3 本里 1 本有 201 处提醒待处理 → 这一条是这屏最重要的改动。现在整屏只有状态，没有指引。

章节工作台 现有 17 个按钮 → 主行 2 个 + 工具行 4 个

这屏是你抱怨最狠的那屏。17 个按钮里，只有 1 个是主行动，其余 16 个都在和它抢注意力。

现在决定改后理由
按目录检查并生成建议 留位，文案随情境 获取参考目录 ／ 直接修复 ／ 保存章节树 … 按钮位置对，但文案写死了。情境不同，该做的事就不同——详见效果图那七种情境。
选择参考目录… 识别设置… 撤销 重做 降级 底部工具行：撤销重做专项处理 ▾ 前两个是一次性设置（设完就不动），后两个是标准编辑动作。都不该占主行。
忘记这份目录（常驻胶囊） 收进菜单 「参考目录」行尾 ▾ 里 它是破坏性的（丢掉已保存的目录），现在却常驻在最显眼处，和状态文字并排。
重新识别章节（会替换手工调整） 收进菜单 专项处理 ▾ → 重新识别章节 会丢掉手工调整。破坏性动作放在右栏正文里，紧挨着只读信息，很容易误点。
上一组 下一组 → 继续加载 已加载 200/331 组 合并 下一组 → 　200 / 331（自动加载到底） 四个控件做一件事：翻页。「继续加载」是分页的实现细节，不该是用户的决定。
取消 应用并返回 保留 + 加量 取消 应用并返回，上方加「将改动原文 12 行 · 新增 43 章」 按之前定的约定：可核对的量就放在提交按钮正上方。现在是空的。
原始 TXT 不变 · 应用并返回后自动保存 改成真话 本次修复：改原文（会写回 TXT，改动前自动备份） 这句是硬编码的，而默认落地模式是 EditSource——执行一次改原文修复后它仍写「不变」。这不是排版问题，是界面在说假话。
三行小字（参考目录 / 当前章节树 / 原文版本，12.5px） 并成一行 chip 标题条下一行：识别规则 现代默认 ▾ 章节树 已保存 原文 正常，13px 你原话「有目录的小字也太小了」。它们该并进标题条，而不是在正文上方再占三行。

目录修复确认窗 现有 3 个按钮 → 3 个，但补两处

这屏的按钮本来就少，问题是文案和它旁边的说明自相矛盾。

现在决定改后理由
应用所选修改 加量 应用 16 项修改 数字进按钮。「所选」是抽象词，16 是确定的。
暂不应用 改名 返回工作台 「暂不应用」听起来像"等等再说"，实际是放弃并退出——用户会以为改动还在。
只改章节树 / 同时改原文 保留，修矛盾 选中「同时改原文」时，说明必须写成：本次 16 项里有 0 项需要改正文，所以原文不会变 截图里选中的是「同时改原文」，而下面写「原文不会有变化」——两句话看起来在打架，用户不知道该信哪句。实际两句都对，是措辞没交代清楚"为什么"。
（缺） 新增 按钮正上方：将改动原文 0 行 · 新增 11 章 · 并回正文 5 处 之前定下的约定，这屏还没有。四个大数字在顶部，离按钮太远。
0 章 · 待你核对（占一个大数字位） 降灰 保留但弱化，不占主数字位 0 是"没有事"，不该和 11 章占同样的视觉权重。

布局规则

三屏共用的四条约束。目的是让用户不需要重新找按钮。

① 每屏一个实心按钮
它 = 这一屏此刻该做的事。其余一律次按钮或纯文字。等重按钮等于没有推荐。
② 状态与动作必须相邻
每个数字旁边有动词（9 需要参考目录 · 获取）。判断来自同一处策略，不会出现"总结说本地能修、点进去却要目录"。
③ 写之前给可核对的量
「将改动原文 N 行 / 新增 M 章」放在提交按钮正上方，不在页面另一头。
④ 底栏说这一次会发生什么
不写固定标语。没有要写回的改动时就说"只改章节树"，而不是永远写「原文不变」。
标题条常驻不动文件名 · 章数 · 识别规则来源 ▾ · 章节树状态
主行动区随情境变数字 + 一句话 + 唯一实心按钮 + 一个次按钮
三个数字常驻不动需要参考目录 / 本地就能修 / 需要你核对，各带动词
正文两栏常驻不动左：提醒列表　右：当前选中项的详情
底栏随情境变落地方式（真话）+ 将改动的量 + 取消 / 应用
工具行常驻不动专项处理 ▾ · 参考目录 ▾ · 撤销 · 重做

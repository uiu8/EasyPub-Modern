# EasyPub Modern v1.57.4 — 你实测反馈的五个问题

基于 v1.57.3，修的是你在真机上走完一次更新后提出的那五条。

## 1. 更新按钮不再掉到窗口外

设置窗固定 780 高，而整个窗口没有滚动。「更新与关于」页在检测到新版本后要展开
更新卡（说明、进度条、安装按钮），内容超出后底部按钮被裁到窗口外，也没有滚动条能找回来。

现在这一页可以滚动了。

## 2. 目录修复的开头不再空白

「书名、书籍网址或番茄编号」这个输入框本来会预填书名，但保存过的目录记录会把它**无条件覆盖**。
而保存记录允许是空的——一键修复、以及从参考目录面板应用时都不传书名——所以只要用过一次
这两个入口，下次打开输入框就是空的。

现在空记录会回退到文件名推导出的书名。

## 3. 改动清单搬进左栏，并且是完整的

这一条是重点。原来那份清单有两个真缺陷，改掉它们只是**一半**，另一半是你后来指出的：

**同一个卷被报了两遍。** 清单按章节树的内部 id 比对，而重建卷层级时每个卷都会拿到新 id，
于是同一个卷既被报成「移除章节项：第N卷」又被报成「新增：第N卷」——原文行完全相同。
更要紧的是「移除章节项」这几个字，读起来像正文被删了。已改为按**稳定身份**比对
（卷看标题、其余看原文行），同一个卷只报一条「建立卷层级」。

**前言被报成被删除。** 前言的 id 同样会变，于是清单里出现「移除章节项：序」。
实际上前言是被复用而非删除，现在不再计入变化。

**清单本身从"一行一条、平铺到几百行"改成按类型归纳**：每类给数量和例子。
真实书稿上：286 项 → 18 项 4 类。而且它现在**跟着你的勾选实时重算**。

然后是你指出的那件事——它之前放错了地方，也没给全：

> 「谁会来下面看这一堆东西？用户需要清晰的知道到底变了什么。」

上一版清单在**右栏明细的末尾**，而且一次只描述**你点开的那一类**。位置在最没人往下滚的地方，
范围要逐类点开才拼得出全貌。现在：

- **左栏就是改动清单**，一行一类改动，每一项都列在下面，**每一项自带复选框**；
- 左栏同时是操作台：在一行上取消勾选，就是取消那一项，右栏的数字跟着变；

```
✓ 标题改按目录写法            2/2
   ☑ 第 43 行 第13章 余烬
   ☑ 第 45 行 第14章 回声
✓ 标题并回正文                1/1
   ☑ 第 41 行 番外 主角的人物卡
● 建立卷层级                  2 卷
   自动 第 1 行 第一卷 风起
   自动 第 20 行 第二卷 云涌
```

- 标注**自动**的行没有方框（它们由对齐过程完成，无法单独取消），那一类因此显示**数量**
  （`2 卷`）而不是分数——`0/2` 会被读成「这两卷不会发生」，而它们一定会发生；
- 右栏改为说明栏：没选中时讲这次修复将做什么，点任意一行就讲那一项；
- 底部仍保留两个**不是改动**的目录事实（参考目录未匹配、疑似公告），单独成区、标题写明
  「不会改动书稿」。

为了让这件事做对，改动落在 Core：**每一条变化现在自己说明它是哪个动作造成的**
（`RepairChange.ActionKey` / `ActionKind`，由 `RepairIntegrity.DescribeWithActions` 装配）。
上一版是在界面层按行号反推，在"标题被并回正文"这类行上必然失败——本该带复选框的行没有复选框，
你也就取消不了它。这也是当初没敢把这件事塞进 v1.57.4 的原因，这次是从根上解决，不是补丁。


## 4. 「将做什么」不再漏报软件会自动做的事

卷层级是由对齐过程内部建立的，原来既不在分类栏里、也没有任何提示，但「实际变化」里
却有它——两个数字对不上，你看不出那 14 条是什么。

现在：

- 侧栏列出「建立卷层级 N 卷」，并标注**自动**（不给复选框：它不是可选项，是这次修复的一部分）；
- 把「章节归入卷层级」（章节从顶层移进卷下）单独成类，不再混进「建立卷层级」——
  混在一起会报出「建立卷层级 16 个」，而实际只有 2 个卷。

## 5. 书源：能看到它到底给了什么

你说「既然已经有三个网站命中，为什么书源这里只能选一个并且不能预览」。查清了，三层原因：

- 书源列表的高亮确实只能一行，但那只决定「操作哪一行」；「启用」列是可多选的，
  真正决定问几个源的是已启用列表。**这不是根因**，所以没动它。
- 真正收敛成一个的是候选目录的取舍逻辑：它静默只留「章节数最多且不少于最大值 90%」的
  第一份，落选源完全不告诉你。**现在会把落选的列出来**——「另有 2 份目录未采用（本次只用一份）：
  a.com 210 章、b.com 198 章」。
- 书源窗口确实没有预览和打开的能力。**现在加了「预览目录」和「浏览器打开」**：
  前者只查你选中的那一个源、把目录标题列出来给你看；后者打开该源的搜索页，
  方便你自己核对或完成登录。

预览只读公开目录、不下载正文。

## 怎么验证的

- `EasyPub.Core.Tests` **431 通过 / 0 失败**
- `EasyPub.Desktop.Tests` **128 通过 / 0 失败**
- 新增的测试锁住行为：卷重建只算一条结构变化、改写标题不再算新增、真正的新增仍算新增、
  前言不算移除、默认全选必须守住三条红线（手工编辑过的章节永不被预选、
  正文不一致的重复不替你删、目录外章节不预选）、**每条变化都指向造成它的那个动作**、
  **自动类改动不带动作**、自动类分组显示数量而不是分数
- 用探针渲染**真实窗口**核对了左栏改动清单与数字自洽，浅色与深色各一张

## 还没验证的

- **这一版的自更新路径没有实测。** 要按惯例用上一版便携版当「已装旧版本」跑一遍
  检查更新 → 关闭 → 自动覆盖重启。
- 说明书源预览与浏览器打开只做了编译与逻辑核对，**没有对每个书源逐个实测**
  （站点可用性随时会变，这也是「检测可用性」存在的理由）。
- 一个已知缺口：**目录有、但原文中定位不到行的章节不进改动清单**（它不产生任何树变化，
  所以没有可勾选的行），只体现在头部的「章需你核对」。真实书稿里这类通常是个位数。

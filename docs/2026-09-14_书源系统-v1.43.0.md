# 书源系统：可选择、可检测、可自己加（v1.43.0）

## 这一版解决的四件事

1. 目录书源从写死的 5 个，变成**用户可排序、可启停、可自己添加**的列表
2. 默认顺序 **起点、番茄优先**（它们的目录带出版社自己的分卷）
3. 目录辅助面板新增 **书源…**：改顺序、**检测可用性**、填 Cookie、加自己的源
4. 章节工作台的 **一键修复** 改成主色大按钮并移到最前

## 番茄小说的实测结论

先把结论说清楚，因为这决定了番茄是怎么接进去的。

| 能力 | 是否需要签名 | 实测结果 |
| --- | --- | --- |
| 书籍目录页 `https://fanqienovel.com/page/<bookId>` | **不需要** | 服务端渲染，直接 GET 就拿到完整分卷目录 |
| 同域接口 `/api/book/info`、`/api/rank/recommend/list` | **不需要** | 返回真实 JSON |
| 关键词搜索 `/search/<书名>` | **需要**（字节风控签名） | 页面本身是 SPA，数据接口不带签名不返回内容 |

实测《十日终焉》（bookId `7143038691944959011`）：目录页 638,913 字节，
解析出 **10 卷 1496 章**，卷名是 `第一卷：我听到了你们` … `第十卷：这一切的终焉`，
不是"第N卷"占位符。

搜索这条路走不通的证据：用系统 Edge 无头渲染 `/search/十日终焉`（10 秒虚拟时间、
真实 UA、禁用自动化特征），页面渲染完成，正文却渲染出 **"共 0 项相关的结果 ·
没有搜索到相关结果"**——服务端风控识别了无头浏览器并返回空集。逆向 `a_bogus`
签名不在本项目的范围内，硬做也会随对方改版立刻失效。

因此番茄源做成 **"仅网址/编号"**：

- 书源列表里能力列显示"仅网址/编号"，检测时明确说明它不参与书名搜索
- 用户把 `https://fanqienovel.com/page/xxxxx` 粘贴到 **备用入口 · 网址**，或直接把
  ID 填进书名框，即可读出分卷目录
- 书名框里粘贴任意公开书籍网址都会被识别（`DiscoverAsync` 开头就判断），
  这条对起点、和图书同样有效

## 书源模型

`src/EasyPub.Core/BookSource.cs`

```csharp
public sealed record BookSource
{
    public string Id { get; init; }            // 稳定键，映射规则引用它
    public string Name { get; init; }          // 显示名
    public string SearchUrl { get; init; }     // 搜索模板，{q} 替换为书名
    public string? DirectUrl { get; init; }    // 直接编号模板，番茄用
    public string? Cookie { get; init; }       // 需要登录的站点
    public bool Enabled { get; init; }
    public int Priority { get; init; }         // 越小越先问
    public bool BuiltIn { get; init; }
}
```

内置 6 个源，默认顺序：

| 顺序 | Id | 名称 | 能力 |
| --- | --- | --- | --- |
| 1 | `qidian` | 起点中文网 | 搜索 + 网址 |
| 2 | `fanqie` | 番茄小说 | 仅网址/编号 |
| 3 | `hetushu` | 和图书 | 搜索 |
| 4 | `shudugu` | 书读谷 | 搜索 |
| 5 | `ixdzs` | 爱下电子书 | 搜索 |
| 6 | `owlook` | 偶书网 | 搜索 |

**合并规则**（`BookSourceCatalog.Merge`）：启动时把内置源并回用户列表。
用户改过的启用状态、顺序、Cookie、自定义源全部保留；**搜索地址由代码拥有**，
所以修好一个内置源的地址，老用户下次启动就能拿到，不需要手工改。
用户新增的源永远不会被覆盖。

存储位置 `%LOCALAPPDATA%\EasyPub Modern\book-sources.json`，原子写入。

**老 Cookie 自动继承**：以前单独存在 `qidian.cookie` 里的起点会话，
在第一次加载书源列表时会被折叠进 `qidian` 源，用户不需要重新粘贴。

## 按文件夹指定优先书源

元数据映射规则新增第三个字段：

```csharp
public sealed record FolderMetadataRule(
    string FolderPath,
    BookMetadataOverrides Metadata,
    IReadOnlyList<string>? PreferredSources = null);
```

场景就是用户提的那个：某个文件夹里的书全部来自一个网站。
给这个文件夹建一条规则、勾上优先书源，之后这个文件夹里每本书都先问那个网站。

`MetadataMappingResolver.Preview` 会在"已应用"列里显示 `优先书源=番茄小说`，
所以在映射预览窗口里就能核对规则有没有按预期生效。

一键修复（`ChapterAutoRepair.RepairAsync`）和目录辅助面板都会读这条规则。

## 检测可用性

`ReferenceCatalogClient.ProbeAsync(source, sampleBook)` 用**用户当前这本书的书名**
去真实搜一次，三档结论：

- **可用** —— 搜索命中，可以继续读它的目录
- **受限** —— 站点打得开，但没搜到这本书（书名不同 / 站点改版 / 该站确实没有）
- **不可用** —— 连接失败，附上原因

检测用书名可以现场改，默认取当前书稿的文件名。
"打得开但搜不到"从来不显示成健康——那正是用户最容易被误导的情况。

## 一键修复按钮

之前它和"识别设置…""结构整理…"长得一模一样、排在第三个。
现在：主色背景、15 号半粗体、42 高、扳手图标，**排在最左**。

样式用 `DynamicResource` 取色（不是 `StaticResource PrimaryButton`），
因为单元测试会直接构造 `ChapterEditorWindow` 而不启动 `App`，
静态引用具名资源会让 25 个窗口测试在 XAML 解析阶段就炸掉。

## 自定义书源

`BookSourceCatalog.CustomId` 从主机名派生 id（`custom:example.com`），
同名站点只允许一个，地址可以直接改。

搜索地址只要满足公开 HTTP/HTTPS、默认端口、不带凭据，
解析全部走既有的结构无关策略（`<dl>` 优先，其次同前缀链接分组），
所以绝大多数"搜索页 → 书籍页 → 目录页"的网站不需要写代码就能用。

### 真实书源检测（本机实跑，2026-09-14）

`chapter-audit <txt> sources` 与设置对话框走同一段代码：

```
书源 6 个（6 启用）
检测用书名：凡人修仙传
  [受限]   起点中文网（搜索 + 网址）   241ms   站点可访问，但没搜到这本书
  [可用]   番茄小说（仅网址/编号）     440ms   可直接读取书籍网址或编号
  [可用]   和图书（搜索）              412ms   已命中
  [可用]   书读谷（搜索）             1604ms   已命中
  [可用]   爱下电子书（搜索）         1555ms   已命中
  [不可用] 偶书网（搜索）              665ms   403 Forbidden
```

起点显示"受限"是正确的：没有配 Cookie 时它确实搜不到，
而不是把它显示成健康、让用户在"为什么没有卷"上浪费时间。

### 真实目录对齐（本机实跑）

| 书 | 源文本 | 参考目录 | 重建 | 缺 |
| --- | --- | --- | --- | --- |
| 沧元图 | 5.89 MB / 完整 | 29 卷 766 章 | **29 卷 767 章** | 3 |
| 大道朝天 | 1.06 MB / 只到 144 章 | 12 卷 1022 章 | 10 卷 170 章 | 852 |
| 凡人修仙传 | 0.18 MB / 只到 30 章 | 13 卷 2453 章 | 4 卷 33 章 | 2420 |

后两行的"缺"不是对齐失败：源 TXT 本身只有 0.18 MB 和 1.06 MB，
`重建` 与文件里的实际章节数吻合。软件把这些如实报出来，
而不是拿一个好看的百分比糊过去。

离线测试覆盖的关键回归点：

- 番茄卷标题不会带上"共N章"后缀
- 每章归属到它自己那一卷（不是全部塞进第一卷）
- 合并内置源时保留用户的启停、顺序、Cookie，并接纳新增的内置源
- 损坏的书源文件回退到内置列表而不是抛异常
- `{q}` 模板替换与转义
- 文件夹规则的优先书源经过保存/加载仍然存在

## 仍未解决

- **番茄书名搜索**：需要字节风控签名，本版不做。
  用户仍可粘贴网址/编号，或让另一个源提供参考目录。
- **`tomato` 那 7 本书**：如果它们没有可用的公开目录页 ID，仍然会显示"无参考目录"。
  这不是伪装成成功的地方——软件会如实说没有取得目录。
